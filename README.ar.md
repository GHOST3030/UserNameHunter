# UserNameHunter (GhostUsernameHunter)

*[Read this in English](README.md)*

أداة سطر أوامر مبنية بـ Node.js تُولّد أسماء مستخدمين مُرشّحة وتفحص نقطة
نهاية (endpoint) لتسجيل الدخول أو التسجيل في موقع مستهدف (عبر HTTP GET أو
POST) لمعرفة الأسماء الصالحة منها، باستخدام بروكسيات HTTP متعددة يتم
التبديل بينها لتوزيع الطلبات.

> **استخدمها فقط على أنظمة تملكها أو حاصل على إذن صريح لاختبارها.**
> تعداد أسماء المستخدمين تلقائيًا ضد خدمات تابعة لجهات أخرى دون إذن قد
> يخالف شروط الاستخدام الخاصة بها والقوانين المعمول بها. هذا المشروع
> مخصّص لأغراض اختبار الاختراق المصرّح به والبحث الأمني.

## آلية العمل

- `src/main.js` يشغّل الحلقة الرئيسية: يولّد اسم مستخدم عشوائيًا (عبر
  `generateAlphaNumUsername`/`generateUsername` في `src/Utils.js`)، ويتخطاه
  إن كان قد اختُبر سابقًا (المُسجَّل في `tested_usernames.txt`)، ثم يرسل
  طلبًا إلى الرابط `url` المُهيَّأ، ويصنّف الاستجابة كصالحة أو غير صالحة.
- `src/Utils.js` يبني الطلب الصادر (`sendRequest`)، ويختار بروكسي عشوائي من
  `src/proxies.js` لكل طلب، ويرسل اختياريًا طلب تسجيل خروج (`Logout`) بعد
  كل نتيجة صالحة.
- `src/config.js` / `src/config.json` يحتويان إعدادات التشغيل (رابط الهدف،
  طريقة HTTP، طول/بادئة/لاحقة اسم المستخدم، مجموعة الأحرف، وعدد الأسماء
  المراد توليدها). يتم فحص `src/config.js` بشكل دوري لرصد أي تغيير، بحيث
  يمكنك تعديل `src/config.json` أثناء تشغيل الأداة وستُعاد قراءته تلقائيًا.
- `src/variables.js` يشتق ترويسات الطلب (headers) وطول الجزء العشوائي من
  الإعدادات.
- `src/Logger.js` يطبع لافتة بدء التشغيل مع الإعدادات الحالية، ويسجّل
  النتائج الصالحة (مع الوقت) في `valid_usernames.txt`؛ أما المحاولات غير
  الصالحة فتُطبع في الطرفية فقط.
- `tested_usernames.txt` يجمع كل اسم مستخدم تم تجربته حتى لا تتكرر المحاولات
  عند إعادة التشغيل.
- `EnterValues.js` أداة تفاعلية (`npm run config` أو `node EnterValues.js`)
  لتعديل `src/config.json` دون الحاجة لتحرير JSON يدويًا.
- `RunTool.js` هو نقطة الدخول للبرنامج؛ فهو ببساطة يستورد ويستدعي `run()`
  من `src/main.js`.

## المتطلبات

- [Node.js](https://nodejs.org/) الإصدار 18 أو أحدث (المشروع يستخدم وحدات
  ES modules وصيغة `import`/`export` على المستوى الأعلى، معرّفة عبر
  `"type": "module"` في `package.json`).
- npm (مرفق مع Node.js).

## التثبيت

```bash
git clone https://github.com/GHOST3030/UserNameHunter.git
cd UserNameHunter
npm install axios chalk https-proxy-agent
```

> ملف `package.json` في المستودع لا يحتوي حاليًا على قائمة تبعيات، لذا يجب
> تثبيتها يدويًا كما هو موضّح أعلاه. هذا الأمر يثبّت:
> - `axios` – عميل HTTP المستخدم لإرسال طلبات تسجيل الدخول/الفحص
> - `chalk` – لتلوين مخرجات الطرفية
> - `https-proxy-agent` – لتوجيه الطلبات عبر بروكسي HTTP/HTTPS

## الإعدادات

قبل تشغيل الأداة، قم بضبط إعدادات الهدف وتوليد أسماء المستخدمين. يمكنك إما
تعديل `src/config.json` مباشرة أو استخدام المحرّر التفاعلي.

### الخيار أ: المحرّر التفاعلي

```bash
node EnterValues.js
```

سيُطلب منك إدخال:

| الحقل | المعنى |
|---|---|
| Server URL | نقطة النهاية المراد اختبار أسماء المستخدمين عليها |
| Logout URL | رابط اختياري يُستدعى بعد إيجاد اسم مستخدم صالح |
| Method | `GET` أو `POST` |
| Total Username Length | الطول الكلي لأسماء المستخدمين المولَّدة |
| Digits for Random Part | مجموعة الأحرف المستخدمة في المولِّد الرقمي |
| Username Prefix / Suffix | نص ثابت يُضاف قبل/بعد الجزء العشوائي |
| Usernames to Generate | عدد المحاولات في هذه الجلسة |

يقوم هذا بكتابة القيم إلى `src/config.json`.

### الخيار ب: تعديل `src/config.json` مباشرة

```json
{
  "url": "http://example.com/login",
  "logout_url": "http://example.com/logout?erase-cookie=yes&var=callBack",
  "method": "POST",
  "length": 10,
  "digits": "0123456789",
  "prefix": "2",
  "suffix": "505",
  "count": 200000000
}
```

- `url` – نقطة النهاية الهدف لإرسال طلبات فحص اسم المستخدم إليها.
- `logout_url` – نقطة نهاية اختيارية تُستدعى بعد إيجاد اسم مستخدم صالح.
- `method` – `POST` أو `GET`.
- `length` – الطول الكلي لكل اسم مستخدم مولَّد (البادئة + الجزء العشوائي +
  اللاحقة).
- `digits` – مجموعة الأحرف المستخدمة في المولِّد الرقمي فقط
  (`generateUsername`).
- `prefix` / `suffix` – نص ثابت يُلصق في بداية/نهاية كل اسم مستخدم مولَّد.
- `count` – عدد المحاولات في تشغيل واحد.

تكتشف الأداة أي تغيير في `src/config.json` أثناء التشغيل وتُعيد التحميل
تلقائيًا (راجع فحص تعديل الملف في `src/main.js`).

### البروكسيات (Proxies)

عدّل `src/proxies.js` وأدرج بروكسيات HTTP/HTTPS التي تريد توجيه الطلبات
من خلالها:

```js
export const proxies = [
  'http://192.168.1.100:8080',
  'http://192.168.1.101:8080',
  'http://192.168.1.102:8080'
];
```

يتم اختيار بروكسي عشوائيًا لكل طلب. يجب توفر بروكسي واحد على الأقل، وإلا
ستفشل الطلبات.

### منطق التحقق من الاستجابة

الدالة `checkfromResponse` في `src/Utils.js` تقرّر ما إذا كان اسم المستخدم
صالحًا:

- إذا كان محتوى الاستجابة نصًا، يُعتبر **صالحًا** ما لم يحتوِ على وسم
  `<input` (مثلًا عند إعادة عرض نموذج تسجيل الدخول).
- إذا كان محتوى الاستجابة JSON، يُعتبر **صالحًا** عندما تكون
  `logged_in === "yes"`.

عدّل هذه الدالة إذا كانت إشارة النجاح/الفشل في هدفك مختلفة.

## الاستخدام

شغّل الأداة من جذر المشروع:

```bash
node RunTool.js
```

ما الذي يحدث:

1. تُطبع لافتة بالإعدادات الحالية (الهدف، الطريقة، صيغة اسم المستخدم،
   العدد).
2. تنتظر الأداة توفر اتصال بالشبكة إلى `url` قبل البدء.
3. في كل دورة (حتى الوصول لـ `count`)، تُولَّد اسم مستخدم جديد، ويُتخطى إن
   كان مسجَّلًا مسبقًا في `tested_usernames.txt`، ثم يُرسل الطلب المُهيَّأ
   عبر بروكسي عشوائي.
4. تُسجَّل أسماء المستخدمين الصالحة في `valid_usernames.txt` مع الوقت
   وتُطبع باللون الأخضر؛ أما غير الصالحة فتُطبع باللون الأحمر.
5. إذا تم ضبط `logout_url`، يُرسل طلب تسجيل خروج بعد كل نتيجة صالحة.
6. يتوقف التشغيل بعد الوصول إلى عدد `count` من المحاولات، أو يمكن إيقافه
   يدويًا بـ `Ctrl+C`.

### ملفات المخرجات

- `tested_usernames.txt` – كل اسم مستخدم تمت تجربته حتى الآن (لمنع تكرار
  العمل بين التشغيلات).
- `valid_usernames.txt` – أسماء المستخدمين التي تم التأكد من صلاحيتها، مع
  الوقت.

## واجهة الويب (Web UI)

فيه واجهة ويب محلية لمن يفضّل استخدام نموذج بدل تعديل ملفات JSON/JS يدويًا.
تعمل بالكامل على جهازك — ما فيه أي شيء يُنشر على الإنترنت إلا إذا سويت
ذلك بنفسك.

```bash
npm install express axios chalk https-proxy-agent
node server.js
```

بعدين افتح `http://localhost:3000` في المتصفح. من هناك تقدر:

- تعدّل رابط الهدف، الطريقة، صيغة اسم المستخدم، العدد، وقائمة البروكسيات،
  وتحفظها في `src/config.json` / `src/proxies.js`.
- تبدأ وتوقف التشغيل بأزرار (هذا يشغّل `node RunTool.js` كعملية فرعية —
  نفس أداة سطر الأوامر الموصوفة أعلاه).
- تشاهد سجل مباشر لكل محاولة عبر Server-Sent Events.
- تشوف أسماء المستخدمين الصالحة فور العثور عليها.

الخادم يستمع فقط على `localhost` افتراضيًا (متغيّر البيئة `PORT` لتغيير
المنفذ). ما فيه نظام مصادقة (authentication)، لذا شغّله فقط على جهاز/شبكة
تثق فيها.

  يحتوي على النسختين المُبهمة والواضحة).
- لا توجد مجموعة اختبارات (test suite) أو أداة فحص أسلوب برمجي (linter)
  مُهيَّأة في هذا المشروع.
